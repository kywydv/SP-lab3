# Лабораторна №3: синтаксичний аналізатор на Flex/Bison

Мова: арифметичні вирази з змінними (`a = 2+3*4; print a;`).
Операції: `+ - * / % ^`, унарний мінус, дужки, коментарі `//`.

## Збірка і запуск
    make
    ./calc input.txt -e                # обчислення
    ./calc input.txt -c out.c          # генерація коду на C
    ./calc input.txt -j ast.json       # AST у JSON
    gcc out.c -o out -lm && ./out
Візуалізація: відкрити `viz.html` у браузері (d3.js), вставити/завантажити `ast.json`.

## Граматика (parser.y)
    program : stmts
    stmts   : stmt | stmts stmt
    stmt    : ID '=' expr ';' | PRINT expr ';'
    expr    : expr op expr | '-' expr | '(' expr ')' | NUM | ID

## Теорія (для захисту)
- Bison генерує LALR(1)-аналізатор: стек станів + таблиці ACTION/GOTO, 1 токен lookahead.
- Shift — перенести токен на стек; reduce — згорнути правило, замінивши його права частину на нетермінал.
- Shift/reduce конфлікт: у стані можна і зсунути, і згорнути (напр. `a+b*c`). Розв'язується
  пріоритетами/асоціативністю (`%left`, `%right`, `%prec`): пріоритет правила порівнюється з пріоритетом токена.
- Reduce/reduce конфлікт: дві різні згортки в одному стані. Bison обирає правило, що йде раніше; краще переписати граматику.
- `-2^2 = -4`: `UMINUS` оголошено нижче за `^`; `^` правоасоціативний.
- LALR vs LR(1): LALR зливає стани з однаковим ядром, таблиці менші, але можливі додаткові reduce/reduce конфлікти.
- Семантика: AST будується в діях правил, потім обхід `run_eval` (обчислення) і `gen_c` (кодогенерація).
